System 1 AI • Structured Decision-Making • บทที่ 24

โมเดลการตัดสินใจเชิงโครงสร้าง และ System 1 AI (Jev)

ก้าวข้ามข้อจำกัดของ LLM เชิงสร้างข้อความ (Generative AI) สู่โมเดลการตัดสินใจความเร็วสูงระดับมิลลิวินาที (System 1 AI) ด้วยสถาปัตยกรรม Jev Model ที่การันตี Type-Safe, ปลอด Prose, และปรับเทียบความน่าจะเป็นอย่างแม่นยำ

1 ทฤษฎีระบบความคิดคู่ (Dual-Process Theory): ปัญหาคอขวดของ AI ยุคปัจจุบัน

ในทางจิตวิทยาและวิทยาศาสตร์การรู้คิด นักเศรษฐศาสตร์รางวัลโนเบล Daniel Kahneman ได้อธิบายการทำงานของสมองมนุษย์ผ่านหนังสือชื่อดัง "Thinking, Fast and Slow" โดยแบ่งการคิดออกเป็น 2 ระบบ:

System 1: คิดเร็ว สัญชาตญาณ (Fast, Intuitive) ~100 ms

การตัดสินใจแบบฉับพลันโดยไม่ต้องอาศัยการแจกแจงเหตุผลเป็นขั้นเป็นตอน เช่น การหลบสิ่งกีดขวาง การอ่านสีหน้าคน การรู้ทันทีว่า $2 \times 2 = 4$ หรือการจัดหมวดหมู่อันตรายทันที

  • ทำงานแบบคู่ขนาน (Parallel & Automatic)
  • ใช้พลังงานต่ำมาก (Low Energy Consumption)
  • มุ่งเน้น "การตัดสินใจและการกระทำ (Action & Decision)"
System 2: คิดช้า ใช้เหตุผลเชิงลึก (Slow, Deliberative) 2,000 - 15,000 ms

การคิดที่ต้องใช้สมาธิและการคำนวณตามขั้นตอน (Chain-of-Thought) เช่น การแก้โจทย์แคลคูลัส การวางแผนเขียนโปรแกรม หรือการประพันธ์บทกวี

  • ทำงานแบบตามลำดับเวลา (Sequential Reasoning)
  • ใช้พลังงานและทรัพยากรสูง (High Compute & Cost)
  • มุ่งเน้น "การอธิบายและสร้างข้อความ (Reasoning & Prose)"

ข้อผิดพลาดทางสถาปัตยกรรมของระบบ Agent ยุคปัจจุบัน

ระบบ AI และ LLM Agents ส่วนใหญ่ในปัจจุบันถูกสร้างขึ้นโดยใช้โมเดลประเภท System 2 (เช่น GPT-4o, Claude 3.5 Sonnet, o1) มาทำงานทุกอย่าง ตั้งแต่งานวิเคราะห์เหตุผลซับซ้อน ไปจนถึงงานเล็กๆ เช่น:

1. Intent Routing: เลือกว่าตั๋วนี้คือเรื่อง Refund หรือ Cancellation
2. Tool-Call Guard: ตรวจว่าคำสั่ง bash นี้ปลอดภัยหรือไม่
3. Context Pruning: เลือกว่าประวัติ tool call ไหนยังสำคัญอยู่

ผลลัพธ์คือ: ระบบเกิดความหน่วงสูง (Latency 1-5 วินาทีต่อการตัดสินใจเล็กๆ), ค่าใช้จ่าย Token พุ่งสูงจากการพร่ำพรรณนาคำพูด (Prose), และความเสี่ยงจากการที่ LLM พ่น JSON ไม่ตรง Schema (Schema Hallucination)

2 สถาปัตยกรรมและหลักการทำงานของ Jev Model

Jev Model (`typesafe/jev-1.13`) โดย TypeSafe AI ถูกพัฒนาขึ้นเพื่อทำหน้าที่เป็น System 1 Decision Engine ที่แท้จริง มันตัดกลไกการสร้างคำพูดทีละคำ (Zero-prose) และมุ่งเน้นการคำนวณการกระจายตัวของความน่าจะเป็น (Probability Distribution) บนปริภูมิการตัดสินใจแบบระบุชนิด (Type-Safe Hypothesis Space)

3 เสาหลักของการตัดสินใจแบบมีโครงสร้าง (The 3 Typed Primitives)

1. Choice

การเลือกตัวเลือกเดี่ยว

รองรับตัวเลือก $2 - 255$ ตัวเลือก โมเดลจะคืนค่าตัวเลือกที่ชนะ พร้อมความน่าจะเป็นแบบสัมพัทธ์ของทุกตัวเลือกและค่าความเชื่อมั่น (Confidence)

Output: choice, probabilities, confidence
2. Score

การประเมินคะแนนถ่วงน้ำหนัก

จัดลำดับคะแนน $2 - 10$ ระดับ (เริ่มนับจาก 0) ผลลัพธ์ไม่ใช่แค่ตัวเลขสุ่ม แต่คือ ค่าคาดหมายถ่วงน้ำหนักความน่าจะเป็น (Expected Value)

$$\text{Score} = \sum_{i=0}^{K-1} i \cdot P(\text{level}_i)$$
3. Noul

ความน่าจะเป็นของ "ใช่" (Prob Yes)

ไม่ใช่แค่การตอบ Boolean (True/False) ทื่อๆ แต่คืนค่าความน่าจะเป็นต่อเนื่อง $P(\text{True}) \in [0.0, 1.0]$ ทำให้กำหนด Guardrail Threshold ได้ยืดหยุ่น

Output: noul = 0.94 (94% Probability)

ทำไม Calibrated Probabilities จึงสำคัญต่อระบบอัตโนมัติ (Automation)?

ใน LLM ทั่วไป หากเราสั่งให้ตอบความมั่นใจ โมเดลมักจะเกิดอาการ Overconfident (ตอบ 99% เสมอแม้จะเดา) หรือตอบเป็นคำพูด เช่น "ค่อนข้างมั่นใจ" ซึ่งคอมพิวเตอร์นำไปคำนวณทางสถิติต่อไม่ได้

Auto-Execution Gate:

หาก $P(\text{Safe}) \ge 0.95$ $\rightarrow$ สั่งให้ระบบรันคำสั่งโดยอัตโนมัติทันทีโดยไม่ต้องรบกวนมนุษย์

Human-in-the-Loop Escalation:

หาก $P(\text{Safe}) < 0.95$ $\rightarrow$ ส่ง Notification ให้วิศวกรกดยืนยันก่อนดำเนินการ

4 สถาปัตยกรรมแบบผสมผสาน (Composite AI Architecture): Jev + LLMs

ในความเป็นจริง เราไม่ได้นำ Jev มาแทนที่ LLM ทั้งหมด แต่เรานำมาทำงานร่วมกันในลักษณะ "System 1 กรองหน้าบ้าน และ System 2 คิดหลังบ้าน" เพื่อดึงจุดเด่นของทั้งสองฝั่งมาผนึกกำลังกัน:

1. Fast Router
คัดกรอง Intent ในระดับ 100ms

เมื่อผู้ใช้ส่งคำขอเข้ามา Jev จะเลือกว่าคำขอนี้ต้องการค้นหาข้อมูลทั่วไป (FAQ), การทำงานกับฐานข้อมูล, หรือต้องการใช้โมเดลคิดวิเคราะห์ ช่วยประหยัดเวลาและค่าใช้จ่ายได้มากกว่า 80%

2. Tool Guard
ตรวจสอบความปลอดภัยก่อนรัน Tool Calls

ก่อนที่ Agent จะรันคำสั่ง bash หรือเขียนทับฐานข้อมูล Jev จะประเมินคะแนน Reversibility และความเสี่ยง หากมีความเสี่ยงสูง จะพักคำสั่งเพื่อรอการอนุมัติจากมนุษย์ทันที

3. Context Compaction
ตัดทอนประวัติที่ไม่จำเป็นเพื่อประหยัด Context Window

แทนที่จะนำข้อความทั้งหมดมาให้ LLM สรุปแบบคลุมเครือ Jev จะตัดสินใจแบบชี้ชัดว่า Tool Call ใดที่ผลลัพธ์หมดอายุแล้ว และส่วนใดที่ต้องคงไว้แบบคงเดิม (Verbatim) สำหรับเซสชันการเขียนโค้ดยาวๆ

ตัวอย่างการเรียกใช้ Jev Decision API ใน Python Python REST 
import requests

url = "https://www.jevai.org/api/v1/decisions"
headers = {
    "Content-Type": "application/json",
    "Authorization": "Bearer YOUR_JEV_API_KEY"
}

payload = {
    "model": "typesafe/jev-1.13",
    "state": "Customer: 'Double charged on my card, refund now!'",
    "questions": {
        "intent": {
            "type": "choice",
            "instructions": "Identify primary customer intent",
            "criteria": {"refund": "Money back", "inquiry": "General question"}
        },
        "needs_human": {
            "type": "noul",
            "instructions": "Requires human intervention?"
        }
    }
}

response = requests.post(url, headers=headers, json=payload)
# Response: ~110ms with guaranteed typed schema
print(response.json())
