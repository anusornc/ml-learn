ML Pipelines & Feature Engineering

การจัดการข้อมูลสูญหาย, แปลงข้อมูลเชิงกลุ่ม, ป้องกันภัยเงียบ Data Leakage และสร้าง Scikit-Learn Pipeline สู่โปรดักชัน

1 การเตรียมข้อมูลและการจัดการข้อมูลสูญหาย (Data Preprocessing & Imputation)

ในความเป็นจริง ข้อมูลกว่า 80% ที่ได้รับมักมีค่าสูญหาย (Missing Values / NaN), มีสเกลที่แตกต่างกัน และมีตัวแปรประเภทข้อความที่โมเดลทางคณิตศาสตร์ไม่สามารถคำนวณได้โดยตรง

SimpleImputer

เติมค่าที่หายไปด้วยค่าทางสถิติ เช่น mean, median (เหมาะกับข้อมูลเบ้/มี Outlier) หรือ most_frequent (สำหรับข้อมูลเชิงกลุ่ม)

KNNImputer

ใช้ระยะห่าง Euclidean หา $k$ แถวที่คล้ายคลึงกันที่สุด แล้วนำค่าเฉลี่ยของเพื่อนบ้านมาเติม แม่นยำกว่าแต่กินพลังประมวลผลสูง

IterativeImputer (MICE)

จำลองแต่ละฟีเจอร์เป็นโมเดล Regression โดยใช้ฟีเจอร์อื่นๆ เป็นตัวทำนาย แล้ววนซ้ำจนกว่าค่าจะลู่เข้า

2 การเข้ารหัสตัวแปรกลุ่ม (Categorical Encoding) & การปรับสเกล

กลยุทธ์การเข้ารหัสตัวแปรกลุ่ม (Categorical Encoding)

  • Ordinal Encoding: เหมาะสำหรับข้อมูลที่มีลำดับขั้น เช่น เล็ก (0), กลาง (1), ใหญ่ (2) ห้ามใช้กับข้อมูลที่ไม่มีลำดับ เพราะโมเดลจะเข้าใจผิดว่าค่า 2 มีค่ามากกว่า 0
  • One-Hot Encoding: แตกเป็นคอลัมน์ไบนารี 0/1 เหมาะสำหรับข้อมูลที่ไม่มีลำดับ (Nominal) เช่น ประเทศ หรือ สี (ระวังปัญหา Dummy Variable Trap: ควรตั้ง drop='first' สำหรับ Linear Models)
  • Target Encoding: แทนที่กลุ่มด้วยค่าเฉลี่ยของตัวแปรเป้าหมาย $y$ เหมาะกับกลุ่มที่มีค่าไม่ซ้ำจำนวนมาก (High-cardinality)

ตัวแปลงสเกลข้อมูลตัวเลข (Feature Scalers)

  • StandardScaler: ลบเฉลี่ยแล้วหารด้วย SD: $z = \frac{x - \mu}{\sigma}$ ทำให้ได้ $\mu=0, \sigma=1$ เป็นค่ามาตรฐานสำหรับโมเดลส่วนใหญ่
  • RobustScaler: ลบมัธยฐานแล้วหารด้วย IQR: $z = \frac{x - Q_2}{Q_3 - Q_1}$ ไม่ได้รับผลกระทบจาก Outlier
  • PowerTransformer: ทำ Box-Cox หรือ Yeo-Johnson แปลงข้อมูลเบ้ให้กลายเป็นการแจกแจงแบบปกติ (Gaussian-like)

3 ภัยเงียบที่อันตรายที่สุด: ข้อมูลรั่วไหล (Data Leakage)

Data Leakage คือปรากฏการณ์ที่ "ข้อมูลจากชุดทดสอบ (Test Set) รั่วไหลเข้าไปอยู่ในกระบวนการฝึกสอน (Training)" ทำให้โมเดลได้คะแนนการประเมินในห้องทดลองสูงลิ่วอย่างผิดธรรมชาติ แต่เมื่อนำไปขึ้นใช้งานจริง (Production) ประสิทธิภาพกลับตกฮวบจนสร้างความเสียหาย

⚠️ ข้อผิดพลาดคลาสสิกที่พบบ่อยที่สุด:

# ❌ ผิดมหันต์: ทำ Scaling ก่อนแบ่ง Train/Test!
scaler = StandardScaler()
X_scaled = scaler.fit_transform(X) # <-- คำนวณ Mean และ SD จากทั้งชุดข้อมูลรวมทั้ง Test Set!
X_train, X_test, y_train, y_test = train_test_split(X_scaled, y)

# ✅ ถูกต้อง: แบ่ง Train/Test ก่อน แล้ว Fit เฉพาะ Train!
X_train, X_test, y_train, y_test = train_test_split(X, y)
scaler = StandardScaler()
X_train_scaled = scaler.fit_transform(X_train)
X_test_scaled = scaler.transform(X_test) # <-- ใช้เฉพาะ transform() ห้าม fit()!

4 การประกอบร่าง Pipeline และ ColumnTransformer สู่ Production

ทางแก้ปัญหา Data Leakage อย่างเบ็ดเสร็จและทำให้โค้ดสะอาดพร้อมใช้งานระดับวิศวกรรม คือการใช้ sklearn.pipeline.Pipeline ร่วมกับ ColumnTransformer

from sklearn.pipeline import Pipeline
from sklearn.compose import ColumnTransformer
from sklearn.impute import SimpleImputer
from sklearn.preprocessing import StandardScaler, OneHotEncoder
from sklearn.ensemble import RandomForestClassifier

# 1. ไปป์ไลน์สำหรับฟีเจอร์ตัวเลข
num_pipeline = Pipeline([
    ('imputer', SimpleImputer(strategy='median')),
    ('scaler', StandardScaler())
])

# 2. รวมการจัดการคอลัมน์ประเภทต่างๆ
preprocessor = ColumnTransformer([
    ('num', num_pipeline, num_attribs),
    ('cat', OneHotEncoder(handle_unknown='ignore'), cat_attribs)
])

# 3. ประกอบรวมโมเดลเป็น Full Pipeline ชิ้นเดียว
full_pipeline = Pipeline([
    ('preprocessor', preprocessor),
    ('classifier', RandomForestClassifier())
])

# ฟิตและทำนายได้ในคำสั่งเดียว ปลอดภัยจาก Data Leakage 100%!
full_pipeline.fit(X_train, y_train)
predictions = full_pipeline.predict(X_test)
