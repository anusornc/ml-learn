การคำนวณค่าประเมิน (3 คลาส)

วิธีการคำนวณ Precision, Recall, F1 สำหรับปัญหาจำแนกประเภทหลายคลาส (Multiclass)

1 ทำไมต้องประเมินโมเดลหลายคลาส?

Accuracy บอกภาพรวมว่าโมเดลทายถูกกี่ส่วน แต่ไม่ได้บอกว่าโมเดลพลาดคลาสใดเป็นพิเศษ สำหรับงาน 3 คลาส เราจึงดู Precision, Recall และ F1-score ของแต่ละคลาส แล้วเลือกวิธีเฉลี่ยที่สอดคล้องกับโจทย์

เมตริกที่ใช้ในบทนี้

  • Accuracy — ถูกต้องโดยรวม
  • Precision — สิ่งที่ทายว่าเป็นคลาสนี้ ถูกจริงกี่ส่วน
  • Recall — คลาสจริงนี้ ถูกจับเจอกี่ส่วน
  • F1-score — สมดุลระหว่าง Precision และ Recall
  • ROC AUC — ความสามารถในการจัดอันดับ/แยกคลาสจากคะแนนความน่าจะเป็น

หลักคิดสำคัญ

เมื่อคำนวณเมตริกของคลาส A ให้ถือ A เป็น positive และรวม B กับ C เป็น negative; จากนั้นทำซ้ำแบบเดียวกันกับ B และ C

แนวทางนี้เรียกว่า one-vs-rest และทำให้สูตร TP, FP, FN, TN เดิมใช้กับ multiclass ได้

ภาพรวมก่อนคำนวณทีละขั้น

ไม่ต้องจำทุกสูตรพร้อมกัน: ใน multiclass ให้เลือกคลาสหนึ่งเป็น “positive” แล้วมองคลาสอื่นรวมเป็น “not that class”

1. Accuracy ทั้งระบบ

ค่าบนแนวทแยงคือทายถูก: $15+20+18=53$ จากทั้งหมด $70$

Accuracy = $53/70 = 75.7\%$

2. Precision / Recall ของคลาส B

$TP=20$, $FP=3+5=8$ (ดูคอลัมน์ B), $FN=1+4=5$ (ดูแถว B)

Precision(B) = $20/(20+8)=71.4\%$

Recall(B) = $20/(20+5)=80\%$

3. F1 และการเฉลี่ยหลายคลาส

$F1(B)=2\times\frac{0.714\times0.80}{0.714+0.80}\approx75.5\%$

Macro ให้ทุกคลาสน้ำหนักเท่ากัน; Weighted ให้น้ำหนักตามจำนวนตัวอย่างของแต่ละคลาส

จำง่าย: Precision ถามว่า “ที่ทายว่าเป็น B นั้น ถูกจริงกี่ส่วน?” ส่วน Recall ถามว่า “B จริงทั้งหมด เราจับเจอแล้วกี่ส่วน?”

3 Accuracy: ทายถูกโดยรวมกี่ส่วน?

Accuracy ใช้เฉพาะค่าบนเส้นทแยงมุม เพราะเป็นกรณีที่คลาสจริงและคลาสที่ทำนายตรงกัน

$$Accuracy = \frac{TP_A+TP_B+TP_C}{N}$$
  1. รวมที่ทายถูก: $15+20+18=53$
  2. รวมจำนวนตัวอย่างทั้งหมด: $N=70$
  3. $Accuracy=\frac{53}{70}=0.757$ หรือ 75.7%

ตีความให้ถูก

75.7% หมายถึง ในตัวอย่าง 70 รายการ โมเดลทายถูก 53 รายการ ไม่ได้หมายความว่าโมเดลทำได้ดีเท่ากันทุกคลาส

เมื่อข้อมูลไม่สมดุล เช่น คลาสหนึ่งมี 95% ของข้อมูล Accuracy อาจดูสูงแม้โมเดลแทบไม่จับคลาสส่วนน้อยได้ จึงต้องดู Precision, Recall และ F1 ร่วมด้วย

4 Precision และ Recall: ดูความผิดพลาดคนละด้าน

Precision — ดูจากคอลัมน์

เมื่อโมเดลพูดว่า “เป็นคลาสนี้” มันพูดถูกกี่ส่วน จึงสนใจ False Positive

$$Precision_i=\frac{TP_i}{TP_i+FP_i}$$

ตัวอย่างคลาส B: $TP_B=20$, $FP_B=3+5=8$

$Precision(B)=\frac{20}{20+8}=0.714$ หรือ 71.4%

Recall — ดูจากแถว

จากตัวอย่างที่เป็นคลาสนี้จริงทั้งหมด โมเดลจับเจอแล้วกี่ส่วน จึงสนใจ False Negative

$$Recall_i=\frac{TP_i}{TP_i+FN_i}$$

ตัวอย่างคลาส B: $TP_B=20$, $FN_B=1+4=5$

$Recall(B)=\frac{20}{20+5}=0.800$ หรือ 80.0%

คลาสPrecision: $TP/(TP+FP)$Recall: $TP/(TP+FN)$อ่านอย่างไร
A$15/18=0.833$$15/20=0.750$ทาย A แล้วมักถูก แต่ยังพลาด A จริง 5 รายการ
B$20/28=0.714$$20/25=0.800$จับ B ได้ดี แต่ที่ทาย B มีบางส่วนเป็น A หรือ C
C$18/24=0.750$$18/25=0.720$Recall ต่ำสุดในสามคลาส จึงควรตรวจเหตุที่ C ถูกสับสน

5 F1-score และการเฉลี่ยผลหลายคลาส

F1 เป็นค่าเฉลี่ยแบบ harmonic mean จึงสูงได้ก็ต่อเมื่อทั้ง Precision และ Recall สูง ไม่ยอมให้ด้านหนึ่งดีมากกลบอีกด้านที่ต่ำมาก

$$F1_i=2\times\frac{Precision_i\times Recall_i}{Precision_i+Recall_i}=\frac{2TP_i}{2TP_i+FP_i+FN_i}$$

คลาส A

$F1_A=\frac{30}{30+3+5}=0.789$

คลาส B

$F1_B=\frac{40}{40+8+5}=0.755$

คลาส C

$F1_C=\frac{36}{36+6+7}=0.735$

วิธีเฉลี่ยวิธีคิดค่าจากตารางนี้เหมาะเมื่อ
Macroเฉลี่ยค่าแต่ละคลาสเท่ากันMacro Precision = 0.766
Macro Recall = 0.757
Macro F1 = 0.760		ทุกคลาสสำคัญเท่ากัน หรืออยากเห็นผลต่อคลาสส่วนน้อย
Microรวม TP, FP, FN ก่อน แล้วคำนวณครั้งเดียวPrecision = Recall = F1 = 0.757งาน single-label ที่ต้องการภาพรวมตามจำนวนตัวอย่างทั้งหมด
Weightedเฉลี่ยโดยถ่วงน้ำหนักด้วย support ของแต่ละคลาสWeighted F1 = 0.757ต้องการสะท้อนสัดส่วนข้อมูลจริง แต่ไม่อยากให้คลาสใหญ่ครอบงำทั้งหมด

Weighted F1 คำนวณจากค่าจริงก่อนปัดเศษ: $(20\times0.78947+25\times0.75472+25\times0.73469)/70\approx0.7575$ จึงอาจต่างเล็กน้อยหากนำค่า F1 ที่ปัดเศษแล้วมาคิดต่อ

6 ROC AUC สำหรับงาน 3 คลาส

ROC วาดความสัมพันธ์ระหว่าง True Positive Rate กับ False Positive Rate เมื่อเลื่อน threshold ของ คะแนนความน่าจะเป็น ส่วน AUC คือพื้นที่ใต้เส้น ROC — ค่าใกล้ 1 แปลว่าโมเดลแยกคลาสได้ดี

One-vs-Rest (OvR)

  • คำนวณ A vs not-A, B vs not-B, C vs not-C
  • จึงได้ ROC/AUC 3 เส้น
  • อาจสรุปด้วย Macro AUC: $\frac{AUC_A+AUC_B+AUC_C}{3}$

One-vs-One (OvO)

  • เปรียบเทียบคู่ A-B, A-C และ B-C
  • สำหรับ 3 คลาส มี 3 คู่: $\binom{3}{2}=3$
  • เหมาะเมื่ออยากดูว่าโมเดลสับสนระหว่างคู่ใดเป็นพิเศษ
ข้อจำกัดของตารางนี้: Confusion Matrix เกิดจาก threshold ที่เลือกแล้ว จึงคำนวณ AUC จริงไม่ได้ ต้องมี score/probability ของแต่ละตัวอย่างหลาย threshold ก่อน

ROC/AUC Explorer: ดูเส้นโค้งและเลื่อน threshold

เลือกคลาส แล้วเลื่อน threshold เพื่อดูว่า TPR และ FPR เปลี่ยนอย่างไร จุดและเส้นด้านล่างเป็น ข้อมูลคะแนนความน่าจะเป็นตัวอย่าง เพื่อสาธิตหลักการ ไม่ได้คำนวณจาก Confusion Matrix ด้านบนโดยตรง

7 เลือกเมตริกให้ตรงกับผลกระทบของความผิดพลาด

เมตริกข้อดีระวังเลือกใช้เมื่อ
Accuracyเข้าใจง่าย เห็นภาพรวมเร็วหลอกได้เมื่อข้อมูลไม่สมดุลคลาสสมดุล และต้องการผลประเมินเบื้องต้น
Precisionช่วยลด False Positiveอาจพลาด positive จริงมากเช่น ตรวจจับสแปม หรือการแจ้งเตือนที่ผิดพลาดมีต้นทุนสูง
Recallช่วยลด False Negativeอาจเตือนเกินและได้ false alarm มากเช่น คัดกรองโรคหรือภัยคุกคาม ที่ไม่อยากพลาดกรณีจริง
F1 / Macro F1บังคับให้พิจารณา Precision และ Recall พร้อมกันไม่บอกต้นทุนของ FP/FN ที่ต่างกันข้อมูลไม่สมดุล หรือทุกคลาสสำคัญ
ROC AUCเปรียบเทียบความสามารถในการแยกคลาสโดยไม่ยึด threshold เดียวต้องมี probability score และอธิบายยากกว่าเปรียบเทียบโมเดลหลายตัวก่อนตัดสิน threshold ใช้งานจริง

แนวทางสรุป: อย่าตัดสินโมเดลด้วยตัวเลขเดียว หากข้อมูลไม่สมดุล ให้รายงาน per-class Precision/Recall/F1 พร้อม Macro average; หากมี score ให้ดู ROC AUC เพิ่ม และเลือก threshold ตามต้นทุนจริงของ FP กับ FN
